## Definition of done for each source

1. Verify the supplied edition and hash. Read every substantive page, inspecting
   diagrams and marked examples visually; identify context/front/back matter
   separately. Extraction alone never changes review status.
2. Create a concise source-region-to-idea inventory. Track each distinct method,
   qualification, counterexample, disagreement and process experiment. Give
   every idea a disposition: operational card, contextual explanation,
   corroboration, conflict, deliberately not adopted, or unresolved.
3. Preserve source caveats. Represent cross-book tensions as conditional choices:
   active/passive, short/long, outline/discovery, explicit/implicit and
   chronological/associative order. Do not harmonize them into universal bans.
4. Build retrievable, source-located guidance with recognition cues, procedure,
   anti-triggers, supported invariants and original contrasting applications.
   Preserve old concept IDs. Add distinct concepts and paired concept evals when
   a genuinely new mechanism cannot fit an existing concept; forty is not a cap.
5. Test abstract retrieval without giving the answer through oracle IDs; verify
   full exception transport. Test application and warranted non-application on
   independently adjudicated unseen passages. Authored fixture/reference prose
   is not independent execution evidence.
6. Confirm that the live MCP serves the new knowledge, and that the installed
   ChatGPT/Work host actually retrieves and applies it with the user's narrowest
   authorized mode. A server-rendered finding is host-authored judgment, not a
   second independent editorial opinion.

The idea audit must be independently challenged for omissions. Completion means
comprehensive recorded source coverage and demonstrated bounded application,
not neural-model training, every-idea perfect recall, or guaranteed future
judgment. PDFs and full extracts remain private; only concise paraphrased
methods, original examples and provenance go to the public repository/server.

## Release discipline

Deploy verified server-side knowledge increments through the existing MCP;
do not ask the user to re-upload a ZIP merely because an example card changed.
Update a plugin bundle when its skill, fallback or connection configuration
changes. Keep the existing draft identity and endpoint. Do not publicly launch
or mark book completeness while the required coverage is unfinished.
