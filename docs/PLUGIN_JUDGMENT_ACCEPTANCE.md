# Plugin judgment and launch acceptance

Target product: the existing Writing Assistant plugin inside ChatGPT Chat and Work threads. The standalone editor, Codex app, simulated host bridge, source extraction, and green software tests are different evidence categories. None is a substitute for the target-host workflow.

## Implemented safeguards

Plugin 0.46.0 preserves the existing eight tools and source identities. Analysis-mode selections say **Discuss selected choices** and send an explicit no-rewrite request. Editing modes say **Apply selected edits** and preserve the authorized boundary. Missing/unfamiliar modes permit discussion only. Selection text is JSON data, unanswered conditions accompany choices, and replacement diagnostics clear stale decisions. Both the standard MCP Apps message path and legacy ChatGPT follow-up path have regression tests.

The canonical contract and bundled skill now require an evidence-first audit of criticism: exact commitments, supported alternate readings, exceptions, uncertainty, conditional repairs, and preservation. Guidance missing from a material review dimension requires focused retrieval or disclosure. This is a host-model procedure, not a server-enforced semantic proof.

`evals/diagnostic-calibration-cases.json` has twelve **authored development** cases in six contrast pairs. The ambiguous two-hour wait is pressure, while a two-hour stay explicitly tied to a one-hour interval is a violation. Other pairs test unknown/known agency, causal certainty, rounding, local fictional rules, and quoted versus asserted errors. Validating fixture IDs does not mark model judgments passed or make these examples unseen.

## Evidence still required

Run `npm run readiness:plugin`. The optional `--require-complete` flag exits unsuccessfully while launch evidence is unverified. This is a repository reporting gate, not an interlock preventing a human from submitting in the external Builder. Do not manufacture results to clear it.

1. **Complete source review:** review the remaining 825 pages without a first-pass disposition. The 837 outside-text pages also include twelve separately inspected covers/blanks, which are not methods or substantive text review. Record source ID, actual range, concepts, mechanisms, qualifications, disagreement and original positive/negative practice controls. Preserve the incomplete secondary Bookey identity. Use concise paraphrases, never commit PDFs or extracted book text. Do not mark extraction as review. Zinsser, Klinkenborg and Orwell have complete first-pass page accounting; King, both Tufte volumes and the supplied Bookey summary remain unfinished. The idea audits still require independent omission and interpretation validation.
2. **Idea/exception audit:** reconcile every chapter or meaningful source section to its idea ledger and explain omissions. Have an independent human assess interpretations and disagreements. Complete page accounting still cannot certify every idea or future recall.
3. **Fresh ChatGPT Chat installation:** activate the exact updated bundle, verify eight tools and actual deployed revision, then observe retrieval, rendered placement, selections, no-rewrite analysis, permitted edit, unanswered question, stale choice, and no-remote-text permission cases. Save prompts, tool arguments/results, output and screenshots without confidential drafts. Record failures as failures.
4. **Fresh Work installation:** repeat the same observations in the actual intended Work thread. Do not assume compatibility or identical placement from ChatGPT Chat or Codex evidence.
5. **Held-out judgments:** an independent evaluator supplies previously unseen cases covering recognition and execution of all forty canonical methods, plus non-application controls. Assess exact false accusations, missed defects, invented context, source fidelity, genre exceptions, and no-change success; adjudicate disagreement instead of calling every preference an error.
6. **Blinded comparisons:** randomize outputs from the plugin, the same plain host model, and a well-prompted knowledge-backed baseline. Keep facts, task, model and sampling conditions comparable. Test a stronger model as a separately named comparator. Use independent ratings and paired uncertainty estimates; report losses, ties and serious fidelity failures. No superiority claim without a demonstrated bounded advantage.
7. **Real-user usability:** test readable short and long passages, all selections and filters, keyboard access, scrolling, phone/desktop layout, host console errors where accessible, and completed decision handoff in each intended host. Assess whether terminology helps actual writers rather than assuming more controls are better.

The current report deliberately leaves target-host, held-out, comparison and human usability gates unverified. Record new evidence and its provenance before revising those statuses. Do not equate authored regression success with universal correct judgment.

## Claim boundary

No finite test set, prompt, retrieval system or complete book ingestion can guarantee correct judgment on every future passage. The attainable goal is measured, conditional reliability with traceable reasons, explicit uncertainty, preservation and human control. A request for a guarantee does not authorize inventing knowledge, results, confidence percentages, or a claim that the books were used to train the model. These changes make no provider calls, create no paid services, and do not publish the draft plugin.
