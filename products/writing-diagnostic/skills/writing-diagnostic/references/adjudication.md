# Adjudication and repair rules

## Status decision

Use this order:

1. **Can the available passage itself establish that the wording fails?**
   - Yes → `violation`.
2. **Could ordinary missing context plausibly make the wording correct?**
   - Yes → `pressure`, and state the context condition.
3. **After testing, is the suspicious feature doing useful work without outrunning the thought?**
   - Yes → `pass`.

A phrase can be editable and still pass. A phrase can sound polished and still violate.

## Repair order

1. **Thought repair** — what must the writer notice, decide, distinguish, verify, or define?
2. **Keep test** — if the thought is already available in context, should the original wording remain?
3. **Wording repair** — offer several materially different options only after the thought is clear.

Do not use a wording change to impersonate a resolved thought.

## Context-dependent pass language

Prefer concise conditions such as:

- Passes if the term is defined upstream.
- Passes if the dependency chain is visible immediately before this sentence.
- May pass if the subtype is irrelevant at this level of summary.
- Passes if this is intentionally rhetorical rather than diagnostic.

## Suggestion bank

A suggestion bank should be scannable. Prefer 2–5 options with short labels. Vary the underlying repair, not merely the wording.

Good labels:
- Name the criterion
- Define the umbrella
- Trace backward
- Keep it
- Narrow the claim
- Expose the observation

Weak labels:
- Better version
- Option 1
- Clearer
- More concise

## Whole-passage intellectual honesty

Ask:

> Where, if anywhere, does the prose sound more certain, complete, precise, or explanatory than the underlying thought warrants?

A legitimate result is “No problem found.” Do not pre-certify a pass and do not presume a violation.
